# Variances

A variance is a documented divergence from a recognized **public standard** — a protocol, format, or
published security baseline with an existence independent of this codebase (SMTP, IMAP, HTTP, the
`__Host-` cookie prefix, OWASP ASVS/Top 10, WCAG, an RFC, a W3C/IETF spec, and so on). It is not a
deviation from this fork's own spec, task, or design intent, and not a difference from what 2.5.x
did — this fork diverges from upstream pervasively by design (see CLAUDE.md's opening section), and
from its own earlier plans as scope is refined; neither is noteworthy on its own. Implementation
decisions, scope descopes, accepted currency/warning exceptions, and design trade-offs belong in
`docs/decisions/` instead, one file per decision.

This document is not a changelog. An entry for a variance that is later resolved (the standard is
met) is deleted outright, not left behind as changelog prose.

There are currently no entries.
