# Logging audit — current state (2026-09-05)

Scope: every line this codebase writes to a log — `backend/core/logger.ts` and its 481 call sites,
Fastify's own pino instance, the pre-logger `console.*` output in `core/config.ts`, the admin
Terminal stream (`controllers/terminal.ts` → `pages/AdminTerminal.vue`), the two log-shaped system
flags (`authDebug`, `sqlLog`), the `frontend/` and `blocks/` `console.*` usage, and how all of it
compares with upstream Wiki.js 3.0 (`requarks/wiki`, branch `scarlett`, checked 2026-09-06).

Evidence is drawn from the source tree at `8559fbcbe` and from the log of the `wiki-wiki-1`
container running image `wiki-fork:e4b9f5031` on this machine (about 36 hours of real output,
19,027 lines).

**Verdict: the plumbing is sound and better than upstream's in three places, but the signal-to-noise
ratio at the default level is poor (88% of a quiet day's lines are scheduler heartbeat), the text
format is inconsistent within itself and interleaved with raw pino JSON, and the vocabulary — the
`[ OK ]` / `[ COMPLETED ]` / `Initializing...` banner style — is upstream Wiki.js's, verbatim.**
The recommendations are in [2026-09-05-recommendations.md](2026-09-05-recommendations.md); the
per-file inventory in [2026-09-05-call-site-inventory.md](2026-09-05-call-site-inventory.md).

## 1. Architecture as it stands

```
config.ts init()  ──console.*──▶ stdout      (before WIKI.logger exists)
                                     │
core/logger.ts ─── WIKI.logger.{error,warn,info,debug}(msg, context?)
   │  formats one line (text or JSON)
   ├──▶ console.log(line)             stdout
   ├──▶ backlog ring (100 lines)      replayed to a new admin terminal
   └──▶ ws.emit('log', line)          streamed live to every admin terminal
                                     │
Fastify (pino, level 'info') ───────▶ stdout  (separate producer; JSON always in text mode)
```

- **One logger, four levels.** `verbose`/`silly` are declared for API compatibility with the 2.x
  call sites and are no-ops. `logLevel` picks a threshold by walking `['error','warn','info',
  'debug']` and flipping `ignoreNextLevels` when it hits the configured name.
- **Two output modes.** `logFormat: default` is `ISO-timestamp [instanceId] level: message`, with
  `styleText` colour on the instance id (dim) and the level (bold, red/yellow/green/cyan).
  `logFormat: json` is `{ ...context, timestamp, instance, level, message }`.
- **A second producer.** `core/http/server.ts` gives Fastify `logger: { level: 'info', genReqId }`.
  In JSON mode it reshapes pino's fields to match the logger's own record; in text mode it leaves
  pino's raw JSON alone. Upstream sets `level: 'error'` and therefore never emits an access log at
  all; the fork turned it on for correlation ids (OpenProject #1937) but only finished the JSON half.
- **Context objects** (`LogContext`) reach the JSON record as sibling fields. In text mode they are
  discarded. Exactly one call site passes one: `helpers/errorHandler.ts#apiErrorHandler`, via
  `helpers/requestLogContext.ts#buildErrorLogContext` (`reqId`, `method`, `url`, `siteId`, `userId`).
- **Error normalisation.** An `Error` passed as `msg` becomes its `.stack` in both modes (#939).
- **The backlog and the terminal** are the fork's only log *consumer*; there is no file, no
  rotation, no shipping. `docs/operations.md#logs` documents this as deliberate.
- **Two runtime switches** produce extra log lines without a restart: `authDebug` (82 call sites,
  all `info`, prefixed `[AUTH]`) and `sqlLog` (`core/db.ts#queryLogger`, `info`, prefixed `[SQL]`,
  parameters redacted to type/length).
- **Workers** (`worker.ts`) build a second logger instance whose `INSTANCE_ID` is the literal
  `'worker'` until the first job overwrites it with the parent's id. Their output goes to the same
  stdout but never reaches the terminal backlog (the `ws` emitter is per-thread).

## 4. Findings

Severity is about operator impact, not code quality. **H** = hides real signal or misleads; **M** =
costs readability or discipline; **L** = polish.

### 4.1 Readability

| # | Sev | Finding | Where |
| --- | --- | --- | --- |
| R1 | H | **Two formats on one stream in the default mode.** Every HTTP request emits two raw pino JSON lines between the coloured text lines. `Server listening at …` appears twice per boot, mid-banner. The admin terminal never sees any of it (pino bypasses the backlog), so the terminal and `docker logs` disagree about what happened. (And what the terminal does see is uncoloured — C7.) | `core/http/server.ts:57-69` |
| R2 | M | **Five prefix conventions, most lines unprefixed.** `(STORAGE/GIT)`, `(SEARCH/ELASTICSEARCH)`, `(SEARCH)`, `${LOG_PREFIX}` (sftp), `[SQL]`, `[AUTH]`. A reader cannot tell a line from `models/hooks.ts` from one from `core/collab.ts` without grepping the source. | throughout |
| R3 | M | **Status tags are decorative, not structural.** `[ OK ]` appears on 49 lines, but so does `successfully`, and `[ COMPLETED ]` vs `[ OK ]` vs `Completed job` vs `Import completed.` all mean the same thing. ### 4.6 Frontend and blocks

- 41 raw `console.warn`/`console.error` calls across 20 files, with four phrasings for the same
  situation: `console.warn(err)`, `console.warn(err.message)`, `console.warn(apiErrorMessage(err))`,
  `console.warn('Failed to …', err)`. No prefix, no gating on `import.meta.env.DEV`, so production
  users' consoles carry them all.
- `stores/page.js` alone has 7; `stores/site.js` 5, all `console.warn(err.message)` in `catch`
  blocks that also toast — the console line is a duplicate of what the user was already shown.
- Nothing is collected: no `app.config.errorHandler`, no `unhandledrejection` listener (N10).
- Blocks: 3 calls, each a sensible one-off. `block-pdf` prefixes itself (`block-pdf: …`); the other
  two don't.

## 6. What is worth keeping

- The single-producer design with a ring buffer and a live websocket. It is small, it works, and
  it is the right shape for a self-hosted wiki that ships as one container.
- The `msg, context?` signature and the JSON record shape (`timestamp`, `instance`, `level`,
  `message`, siblings from context). It only needs the text formatter to honour context too.
