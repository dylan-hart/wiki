# WP 3770 comment recommendations

## backend/api/notes.ts, `routes` (above the first route, after the `fastifyMultipart` registration)

**Add.** Proposed:

```
// No route-level permissions: notes belong to their owner alone, so no global, page or site
// permission applies. `notesCaller` requires a signed-in user and the site's `features.notes`,
// and every model call is filtered on (siteId, userId), so another user's row answers 404.
```

Reason: this is the fork's convention for flagging a route that deliberately declares no
`config.permissions` (CLAUDE.md's Permissions section, and #3770's own acceptance criteria). It
also says where the security check sits, which the code alone doesn't point to.

## backend/api/notes.ts, `routes` (the `PUT /sites/:siteId/notes/sections/order` and `PUT /sites/:siteId/notes/order` handlers, above the owned-ids check)

**Add.** Proposed:

```
// Checked here, not left to the model, so that one foreign id rejects the whole reorder with 404
// before anything is written.
```

Reason: the check repeats one the model may also make, and without the why a reader might remove it
as redundant. The whole-request rejection is load-bearing for the existence-leak guarantee.
