# Comment recommendations: WP #3771 (promote a note to a wiki page)

The work package forbids editing code comments. These are the changes I recommend making, judged
against the rubric in the user's CLAUDE.md.

## `backend/models/assets.ts`, `Assets#upload`, JSDoc above the method

**Change.** The current text reads:

> A file already at this name is settled per the site's {@link UploadConflictBehavior}. An
> overwrite returns the existing asset's ID, and the name is sanitized, so a caller that means to
> link to what it just uploaded must read the returned name and ID rather than assume its own.

Proposed text:

> A file already at this name is settled per the site's {@link UploadConflictBehavior}, except
> inside a caller's `tx`, where the arrival always takes the next free name: `replace()` writes
> outside the transaction, and a promotion must never overwrite another page's file. An overwrite
> returns the existing asset's ID, and the name is sanitized, so a caller that means to link to what
> it just uploaded must read the returned name and ID rather than assume its own.

Reason: the comment no longer matches the code. With `tx` set, `behavior` is forced to `'new'`.

## `backend/models/assets.ts`, `Assets#upload`, the `tx` / `afterCommit` parameters

**Add**, as JSDoc on the two new fields of the parameter type:

> `tx`: writes the tree and asset rows through the caller's transaction (`helpers/notePromotion.ts`).
>
> `afterCommit`: receives the text-extraction job, the `asset:upload` announcement and the log line
> instead of running them. The caller runs them only once its transaction has committed, because a
> hook or storage dispatch for a rolled-back asset would announce a file that does not exist.

Reason: the code relies on this constraint but does not enforce it. A caller that passes `tx`
without `afterCommit` announces an asset before its commit.

## `backend/models/assets.ts`, `Assets#upload`, the `catch` around the `assets` insert

**Change.** The current text reads:

> -> Nothing points at the tree row now, and leaving it would show a file the site cannot serve

Proposed text:

> -> Nothing points at the tree row now, and leaving it would show a file the site cannot serve.
> Inside a caller's transaction the failed statement has aborted it, and its rollback removes the
> row instead.

Reason: the comment now sits over `if (!tx)`, and the `tx` branch is left unexplained. The wording
mirrors `models/pages.ts#insertPageRows`'s comment on the same case.
