# WP 3557: recommended comment changes

Comments were not edited in code; apply these by hand.

## `backend/db/schema.ts`, doc comment on `auditLog` (the narrow-scope note)

Current:

```ts
/**
 * Instance-wide, permission-affecting events. Page content edits are deliberately absent:
 * `pageHistory` already records them per page, with the diff/restore machinery this table lacks.
 *
 * Append-only: the only deletions are the retention job (`tasks/simple/clean-audit-log.ts`).
 */
```

Recommended:

```ts
/**
 * Instance-wide, permission-affecting events, including an account's own security events
 * (register, password reset, 2FA and passkey enrol/remove, logout). Page content edits are
 * deliberately absent: `pageHistory` already records them per page, with the diff/restore
 * machinery this table lacks.
 *
 * Append-only: the only deletions are the retention job (`tasks/simple/clean-audit-log.ts`).
 */
```

## `backend/api/auditLog.ts`, `GET /` description

The description string lists "user/group/permission changes, API key issuance, ... and login history". Add "an account's own password-reset, 2FA, passkey, registration and logout events" (this is an API description string, not a code comment, so it is listed here only so it is not forgotten).

## `backend/models/auditLog.ts`, above `'user.registered'` in `AUDIT_EVENTS`

Optional one-liner: the eight `user.*` entries from `user.registered` to `user.loggedOut` are self-initiated, recorded with the account holder as actor; `detail` carries only closed fields (`strategyId`, `passkeyId`), never a token, code or password. `user.passwordResetRequested` is recorded only after a token is minted, so an unknown address leaves no row.
