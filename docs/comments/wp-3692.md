# WP 3692 comment recommendations

## backend/api/pages/versions.ts, `GET /sites/:siteId/versions/:versionId` route options

**Add**

Proposed text, above `schema:` in the same `// ->` style as `history.ts`'s sibling route:

```ts
// -> No route-level `permissions`: `read:history` is a page permission, checked against the
//    page the version belongs to in the handler
```

Reason: root `CLAUDE.md` requires a `No route-level permissions:` note on a route enforcing a page-scoped permission in its handler, and the handler's `requireReadablePage` call does not say why `config.permissions` is absent. Left out of the code because comments are off-limits to the implementer.

## backend/api/pages/versions.ts, handler after `requireReadablePage`

**Add**

Proposed text, above the `requireReadablePage` call:

```ts
// -> Judged on the page as it stands NOW, not the path the version was written at; a deleted page
//    404s here although its history rows outlive it (`pageHistory.pageId` is not a foreign key)
```

Reason: the ordering (version lookup first, then a permission check on the current page) is what makes a moved or deleted page behave correctly and is not derivable from the call.

## frontend/src/pages/PageVersion.vue, `renderVersion`

**Add**

Proposed text, above the `DOMPurify.sanitize` calls:

```js
// -> Sanitized in the browser: an old version's source is untrusted HTML (`allowHTML`), and unlike
//    a saved page it never passed the server's `helpers/htmlSanitizePolicy.ts`
```

Reason: without it a reader may remove the sanitize call as redundant with the server; it is the only barrier between an old version's markup and the viewer's origin.
