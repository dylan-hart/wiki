# WP 3807 comment recommendations

## backend/core/collab.ts, `publish`

**Change**

Current:

```
/**
 * Never awaited — every caller is a Yjs handler reacting to an edit or a cursor moving, and a
 * keystroke cannot wait for a round trip to postgres. The notifier (`helpers/pubsub.ts`) queues
 * sends, which is what makes that safe on a single client.
 */
```

Proposed:

```
/**
 * Never awaited: callers are Yjs handlers and the relay-outbox flushes, none of which can wait
 * for a round trip to postgres. The notifier (`helpers/pubsub.ts`) queues sends, which is what
 * makes that safe on a single client.
 */
```

Reason: "every caller is a Yjs handler" is no longer true. Document updates and awareness changes
now reach `relay()`/`publish()` from timer flushes (`flushRelayUpdates`, `flushRelayAwareness`), and
also from `pageSaved`, `closeRoomIfEmpty` and `shutdown`.

## backend/core/collab.ts, `RELAY_UPDATE_WINDOW` / `RELAY_AWARENESS_WINDOW`

**Add** (one JSDoc above the pair):

```
/**
 * How long a room buffers its outgoing relay. Every NOTIFY commits on its own and queues behind
 * postgres's single notify lock, so a typist's per-keystroke updates go out as one
 * `Y.mergeUpdates` payload per window, and cursors as the latest state per client. Local sockets
 * are never delayed; an awareness removal skips the window so a departed cursor does not linger.
 */
```

Reason: a reader cannot see from the code why cross-instance traffic is delayed at all (the
notify lock), or why removals are the exception. Optional, since the rubric says to add almost
never. If it is taken, the module header's "Across instances" paragraph can stay as it is.

## backend/core/collab.ts, `queueRelayUpdate` / `queueRelayAwareness`

**Add** (one line above the `this.rooms.get(room.pageId) !== room` check in each):

```
// -> A room already closed or shut down sends at once: no timer may outlive its room
```

Reason: without it, the check reads like a redundant liveness test. It is there because anything
queued after `closeRoomIfEmpty`/`shutdown` has run its flush would otherwise start a timer that
fires against a destroyed room. Optional, for the same reason as above.
