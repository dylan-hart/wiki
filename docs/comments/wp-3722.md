# WP 3722 comment recommendations

## backend/api/pageTemplates.ts, `routes`

**Add**

Proposed (above `async function routes`):

```ts
/**
 * No route-level permissions: `write:pages` is a page permission and `site:templates` a site one,
 * neither of which the `config.permissions` hook can check, so each handler asks in its own body.
 */
```

Reason: root CLAUDE.md's Permissions section asks a route that checks in its handler to say so, and
this file is otherwise silent on why no route declares `config.permissions`.

## backend/models/pageTemplates.ts, `sanitizeSource`

**Add**

Proposed (above the function):

```ts
// -> `&` is masked first so every `&lt;`/`&gt;` sanitize-html emits in text is its own and
//    `textFilter` can undo it; otherwise markdown's `>` and `<` come back entity-escaped.
```

Reason: the mask/unmask pairing is load-bearing and not derivable from the code alone.

## backend/models/pageTemplates.ts, `PageTemplates.update`

**Add**

Proposed (above the `content` re-sanitize condition):

```ts
// -> Only re-sanitized when sent (or when `editor` changes the sanitizer): a rename by a
//    lower-privileged editor must not strip a higher-privileged author's markup.
```

Reason: the condition looks like an optimisation but is a permission decision.

## backend/db/schema.ts, `pageTemplates` unique index

**Add**

Proposed (above the `uniqueIndex`):

```ts
// -> `coalesce` because Postgres treats NULLs as distinct in a unique index, which would let two
//    all-locale templates share a name.
```

Reason: without it the expression reads as needless indirection.
