Deploying the runner

The runner is a single binary. Place it on the host, point it at the control plane, and it registers itself under the hostname it finds.

Registration is idempotent. Restarting the runner with the same token reattaches it to the existing record rather than creating a second one.

Each job runs in a fresh working directory that is removed when the job finishes, whether it succeeds or fails. Anything the job wants to keep has to be declared as an artifact.

Artifacts are uploaded after the last step and retained for thirty days by default. The retention window is a per-project setting.

Logs stream while the job runs and are kept alongside the artifacts. The last 200 lines of each step are shown inline on the job page.

If the host loses connectivity mid-job the runner keeps executing and replays the log on reconnect.

Code block · both axes
runner:
  token: ${CARDINAL_RUNNER_TOKEN}
  control_plane: https://ci.internal.example.com/api/v2/runners/register
  workdir: /var/lib/cardinal/runner
  artifacts:
    retention_days: 30
    upload_after: last_step
  logs:
    inline_tail: 200
    replay_on_reconnect: true
  hooks:
    pre_job:  /usr/local/bin/cardinal-pre-job --verify-token --quiet
    post_job: /usr/local/bin/cardinal-post-job --collect-artifacts
